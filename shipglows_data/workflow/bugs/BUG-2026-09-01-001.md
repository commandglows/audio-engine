# Bug Record: BUG-2026-09-01-001

## Summary

- Current status: `fix-attempted`.
- Severity: `high` because the UI falsely reports successful recording after the selected physical input disappears.
- Owner: sg-bug.
- Next action: physically retest endpoint removal and recovery on Windows; closure remains pending.

## Reproduction

- Preconditions: select `Microphone (Senary Audio) [2]` explicitly in ContentGlows and start a Windows recording with observable input signal.
- Steps:
  1. Unplug the selected microphone while recording.
  2. Leave the session untouched and observe the recorder state.
- Result: ContentGlows remained in `Recording in progress` for approximately 10 minutes with no reconnect or error state. A screenshot was supplied by the operator.
- Reproducibility: `1/1` physical attempt on 2026-09-01.

## Expected Behavior

- The engine detects that the explicitly selected endpoint is no longer active.
- It reports `device_invalidated` and enters the existing bounded recovery path without silently selecting another input.
- The UI must not continue presenting a false successful-recording state.

## Diagnosis Notes

| Date UTC | Skill | Author | Hypothesis | Findings | Outcome |
|----------|-------|--------|------------|----------|---------|
| 2026-09-01 | sg-fix | Codex | `RouteMonitorWorker()` only checks endpoint activity when the Windows default input changes. | Confirmed: `IMMDevice::GetState()` was nested inside the default-route-change branch, so unplugging an explicit endpoint while the default remained unchanged was never classified. | supported; direct cause |

## Regression-First Correction Contract

1. Prove that an inactive explicit endpoint is classified `selected_device_lost` even when the default endpoint did not change.
2. Poll the selected endpoint state during capture and trigger the existing `device_invalidated` recovery path when it is inactive or unavailable.
3. Preserve the selected endpoint identity during recovery and never fall back to another microphone.
4. Prove that changing the system default does not replace an active explicitly selected endpoint.
